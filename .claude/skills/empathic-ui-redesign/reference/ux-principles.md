# UX principles: applied checklist

Use these as guidelines, not rigid rules. Combine them, and test with real users when you can.

- **Hierarchy first.** Large bold key figures, muted secondary labels, one clear primary action per view. The element that differs gets noticed first.
- **Familiar patterns (Jakob).** Standard navigation, search and table conventions. People expect your product to work like the others they use.
- **Fewer choices at a time (Hick, Miller).** Group navigation under labeled sections. Split long forms into steps.
- **Proximity, common region, similarity.** Related items live together with consistent spacing on a grid. Same-role elements share one visual style.
- **Fitts.** Primary actions are large and easy to reach. At least 44px targets on touch layouts.
- **Feedback (Doherty).** Immediate loading, success and progress states. Progress indicators on multi-step tasks (goal-gradient, Zeigarnik).
- **Postel.** Be forgiving about input formats (spaces, case, separators, pasted values).
- **Tesler.** Hide unavoidable complexity; do not push it onto the user.
- **Occam.** The simplest solution. No extra screens or controls.
- **Peak-end.** Make completion moments clear and calm.
- **Layout.** Use a grid, consistent spacing, alignment, white space and balance. Respect the F-shaped reading pattern: key content top and left.
- **User control.** Back and cancel are always available. Destructive actions are undoable, or confirmed with clear consequences.
- **Accessibility.** Contrast (4.5:1 body, 3:1 large text and UI parts), visible keyboard focus, real labels, no color-only meaning, responsive down to mobile.
- **Do:** clear navigation, a strong call to action, fast loading, mobile-friendly layouts.
- **Don't:** confusing menus, hidden help or contact, cluttered layouts.
