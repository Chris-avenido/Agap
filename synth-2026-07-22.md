- **Position assignment & assignment-level (SHS / ES / JHS) rules**:

  - Vacancy Count inside card lists is calculated dynamically at runtime using `(SELECT COUNT(*) FROM vacancies v WHERE v.job_cluster_id = c.id AND v.status = 'open' AND (v.filling_up_status = 'UNFILLED' OR v.filling_up_status IS NULL))` in [vacancies.service.ts:12](file:///d:/InsightED/Agap/backend/src/vacancies/vacancies.service.ts#L12) rather than being stored statically in the tables.

    - `requiredBachelorDegree` -> `positions.required_bachelor_degree`
    - `requiredDegreeKeywords` -> `positions.required_degree_keywords`
    - `minYearsExperience` -> `positions.min_years_experience`
    - `minTrainingHours` -> `positions.min_training_hours`
    - `eligibilityRequired` -> `positions.eligibility_required`

  - Viewing/editing applicant details is handled entirely via [ApplicationModal.tsx](file:///d:/InsightED/Agap/frontend/src/components/ApplicationModal.tsx) component.
  - The modal represents the Personal Data Sheet (PDS) form and divides input categories into 10 tab sections:
    - `C1`: Personal Information (Name, Date of Birth, Place of Birth, Sex, Civil Status, Height, Weight, Blood Type)
    - `C2`: Family Background (Spouse, Parents, list of children)

- **Profile Completion Progress Logic**:
  - Computed via `calculateProfileProgress()` in [profileProgress.ts:1](file:///d:/InsightED/Agap/frontend/src/utils/profileProgress.ts#L1).
  - Checks completion of steps: Personal Info, Family Background, Educational Background, Eligibility, Work Experience, Voluntary Work, Learning & Development, Other Info, Legal Questionnaire, and Letter of Intent.
  - Denominator is 10 for normal registration, 11 for subsequent applications (requires active Documents Confirmation step).
  - Percentage score = `(completedSteps.length / totalSteps) * 100`.

- **State Storage Registry**:
  - `localStorage` key `"session_data"` stores user login properties: `{ id: number, applicant_number: string, email: string, expiry: number }`. Read by `ProtectedRoute` to authorize dashboard rendering.

- **Base URL Resolution**:
  - Uses `import.meta.env.VITE_API_URL` to reference the backend server (e.g. `http://localhost:3000`).

## H. Gaps, Risks & Unknowns
- **SSO Fallback bypass**: The backend verification is bypassed or overridden in local development by signing a static JWT. If `VITE_DEV_SSO_TOKEN` or `AGAP_SSO_EMAIL` is missing in staging environments, SSO handshake will fail.
- **LibreOffice dependency**: `POST /api/applicants/convert-pds-to-pdf` uses `libreoffice-convert`. If LibreOffice is not installed on the system (e.g. locally or on server containers), it falls back to returning raw XLSX.
- **Multiple application tables naming**: The schema file [database_sql.txt](file:///d:/InsightED/Agap/database_sql.txt) declares `job_applications`, while backend runtime queries table `applications`. This suggests the table was created/renamed at database deployment time.
- **Prisma Schema Divergence**: The file `backend/database/schema.prisma` contains hundreds of tables from a separate parent dashboard application (InsightED HQ system). However, the AGAP microservice backend runs on native SQL queries and only interacts with a small subset (`applicants`, `applications`, `saved_clusters`, `vacancies`, `job_clusters`, `positions`, `agap_schools`, `qual_evals`, `users`).
